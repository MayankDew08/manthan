14/08/2026, 10:50:00 PM Alice: Full agentic setup dump from that twitter thread, some real good basics in here. I'm just going to dump my whole agentic coding setup because I keep seeing people miss giant chunks of it and it's actively hurting their results. Here is what I have and recommend:
0. An AGENTS.md that acts as a router. It sends the agent to the right skills, docs, and context files before it does anything else. Without this the agent wanders into the wrong folders and guesses instead of reading.
1. A skills directory, one folder per capability. Each folder has a SKILL.md with a precise trigger description and the workflow steps. Keep the triggers narrow, one skill per concern, and never let two skills claim the same trigger.
2. Explicit tool definitions in a separate tools.md including the failure modes. Agents fail because they don't know what breaks, so I document the sharp edges: which flags explode, which commands need root, which APIs rate limit.
3. A memory directory with markdown notes the agent writes after every session: what worked, what failed, and what to try next. This compounds over time and is honestly the highest leverage part of the whole setup.
4. Model choice matters more than prompt length. For local inference I started with a 35b MoE at around 90 tokens per second but it got stuck in thinking loops, adding imports, removing them, re-adding them, never converging. I switched to a 27b dense model at about 50 tok/s and it can run Flutter analyze, interpret the linter warnings, and self-correct in one pass. Raw throughput is not the same as getting the task done.
5. Context budget discipline. I give the agent a hard token budget per session and a dump-and-continue protocol. When it hits the budget it writes a state file and cold-starts with that file as the entry point instead of trying to remember.
6. Test-first scaffolding. Every skill writes a small failing test before it edits any code. The test is the contract. The agent iterates until the test goes green, and then the test stays behind as a regression guard.
7. Session logging. I log every action the agent takes to a session log. You cannot debug what you cannot replay, so after each session I grep the log for RETRY, LOOP, and FAILED to find the weak spots.
The biggest wins I have seen in practice are the router file, the session memory, and forcing the agent to write the failing test first. Everything else is polish on top of those three. Happy to answer follow-ups on any of it.

14/08/2026, 10:52:00 PM Bob: Here is the config I use for the 27b dense model on a 3060, took a while to get stable so sharing the working values. The key knobs are the KV cache quantization and the prompt cache. If you leave flash attention off it drops to 25 tok/s, so do not. Temperature 0.2, top_p 0.9, repetition penalty 1.15. Context 8192 works fine with the 4GB layer offload, above that it spills to CPU and you lose the streaming benefits.
--model 27b-dense-q5 --ctx 8192 --threads 8 --n-gpu-layers 32 --flash-attn on --cache-type-k q8_0 --cache-type-v q8_0 --temp 0.2 --top-p 0.9 --repeat-penalty 1.15 --mlock
I tested the same file with the 35b and it OOMs at 6GB VRAM unless you drop to q4 and lose quality, so the 27b dense is the better tradeoff for 8GB cards.
